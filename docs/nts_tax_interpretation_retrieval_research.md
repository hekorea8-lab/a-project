# 국세법령정보시스템 세법해석례 수집·검색 고도화 조사

## 1. 조사 목적과 결론

이 문서는 국세법령정보시스템의 **공개 세법해석례**를 세법 질의의 보강 근거로 안전하게 수집하고, 법령 조문과 연결해 검색 품질을 높이는 방안을 정리한다. 대상은 국세청이 공개한 화면과 `robots.txt`이며, 비공개 API·로그인 영역·우회 수집은 범위에서 제외한다.

핵심 결론은 다음과 같다.

1. 현재의 ``세목 × 문서유형별 최신 N건`` 수집은 연결 확인용 PoC로는 유효하지만, 실무 질의의 사실관계와 유사한 해석례를 충분히 찾기에는 표본이 작다.
2. 해석례를 하나의 긴 본문으로 저장하거나 앞부분만 LLM에 전달하면 질의·회신·결론·근거 조문이 섞여 검색과 답변 모두 약해진다. 문서의 구조를 보존한 청크와 조문 관계를 별도로 저장해야 한다.
3. 국세청 목록은 등록일자·생산일자 기준의 정렬·필터를 제공하므로, 문서 ID와 최종변경일을 기본 키로 하되 **날짜 워터마크에 중복 구간을 두는 증분 수집**이 적절하다.
4. 수집 단계에서만 공식 사이트를 저속 호출하고, 질문 시에는 승인된 로컬 저장소와 그래프만 검색해야 한다. 법령을 우선 제시하고 세법해석례는 유사 사실관계를 보강하는 용도로 한정한다.

## 2. 공식 원천에서 확인한 범위와 제한

국세법령정보시스템의 [전체 해석례](https://taxlaw.nts.go.kr/qt/USEQTJ001M.do)는 공개 세법해석례를 **사전답변, 질의회신, 과세기준자문, 고시서면질의**로 구분하고, 세목·검색어·등록일자·생산일자 기반 조회를 제공한다. 메인 사이트도 세법해석례와 판례·결정례를 별도 자료군으로 제공한다([국세법령정보시스템](https://taxlaw.nts.go.kr/)).

2026-09-03에 확인한 [robots.txt](https://taxlaw.nts.go.kr/robots.txt)는 `/is/USEISA001M.do`, `/is/USEISA003M.do`를 금지한다. 따라서 빠른 키워드/문장 검색 화면을 자동 수집에 사용해서는 안 된다. 반면, 목록과 상세 화면은 수집 전 매 실행마다 robots 정책을 다시 확인하고, 그 시점의 금지 경로가 아니며 공개적으로 제공되는 경우에만 제한적으로 사용할 수 있다.

공식 화면에 별도의 대량 수집 API 또는 호출량 한도가 공개되어 있음을 확인하지 못했다. 그러므로 "공식 화면이 사용하는 내부 요청"은 안정된 공용 API로 가정하지 않는다. 다음 운영 원칙을 적용한다.

- 로그인, 인증 우회, 캡차 우회, 비공개 요청 헤더·세션 재사용을 하지 않는다.
- `robots.txt` 확인 실패·경로 금지·HTTP 429/403/5xx가 발생하면 해당 실행을 즉시 중단하거나 지수 백오프 후 종료한다.
- 기본 간격은 상세 문서 1건당 최소 1초, 목록 페이지는 최소 2초로 시작하고 동시 요청은 1개로 제한한다.
- 질문 처리 중에는 국세청에 접속하지 않는다. 수집 작업은 사용자가 시작한 갱신 또는 승인된 배치에서만 수행한다.
- 법적 고지에 따라 시스템 자료는 참고자료이므로, 답변에는 문서번호·원문 링크·생산/등록 시점을 함께 표시하고 확정 판단으로 표현하지 않는다.

## 3. 수집 범위: 단계적 확대

### 3.1 1단계 — 현재 세목의 완결성 확보

현재 우선 세목인 법인세·부가가치세·조세특례에 대해 네 문서유형 전체를 수집한다. "최근 N건"만 유지하지 말고, 목록의 생산일자 내림차순을 기준으로 연도별 체크포인트를 두고 과거로 순차 백필한다. 초기에는 최근 5개 생산연도와 해당 세목의 주요 조문/주제별 결과를 우선한다.

### 3.2 2단계 — 업무 영향도 기반 세목 확대

국세기본·국세징수·소득세·상속증여세·국제조세·종합부동산세 등은 PRD의 실제 질의와 Risk Issue 빈도를 기준으로 추가한다. 전체 13만 건 이상으로 표시되는 공개 목록을 한 번에 전수 수집하지 않는다. 세목·문서유형·생산연도별 큐를 만들어 중단·재개 가능하게 운영한다.

### 3.3 3단계 — 판례·결정례와의 결합

세법해석례는 판례·결정례와 같은 권위로 혼합하지 않는다. [국세청 메인](https://taxlaw.nts.go.kr/)이 별도 제공하는 판례·결정례는 기존 국가법령정보센터 판례 원천과 중복 여부·원문 완전성·사건 식별자가 검증된 경우에만 보강한다. 같은 사건/문서의 중복은 출처가 아닌 **정규화된 사건 또는 문서 식별자**로 합친다.

## 4. 권장 저장 모델

### 4.1 원문 보존 레코드

`tax_interpretation_document`는 원문 단위이며, 문서 ID와 버전·출처를 보존한다. 상세 화면에는 문서유형·세목·제목·문서번호·요지 외에도 사실관계, 질의요지, 회신(답변), 관련 법령, 주제어, 유사문서·참조 사례, 첨부가 문서별로 제공될 수 있으므로, 실제 응답의 존재 여부를 `available_sections`로 기록한다. 특정 필드가 모든 문서유형에서 항상 같은 이름으로 제공된다고 가정하지 않는다.

| 필드 | 용도 | 검증 기준 |
| --- | --- | --- |
| `source_system` | `NTS_TAXLAW` 고정 | 공식 도메인인지 확인 |
| `source_document_id` | 목록/상세가 제공한 공개 문서 ID | 비어 있지 않고 원문 URL과 일치 |
| `document_type_code`, `document_type_name` | 사전답변·질의회신·과세기준자문·고시서면질의 | 코드와 표시명이 사전과 일치 |
| `tax_code`, `tax_name` | 세목 | 목록 필터 값과 일치 |
| `document_number` | 사전·서면 등 문서번호 | 제목이 아닌 별도 필드로 보관 |
| `title`, `summary` | 안건 제목과 공식 요지 | HTML 강조표식 제거 후 원문도 보관 |
| `facts_text`, `question_text`, `reply_text` | 사실관계·질의·회신 본문 | 각각 별도 필드, 원시 응답의 필드명과 빈 값 여부 기록 |
| `conclusion_text` | 회신에서 추출한 결론 | 원문 구간·추출 규칙·신뢰도와 함께 보관 |
| `related_law_refs` | 관련 법령명·조문 | 상세 화면의 명시 목록과 원문 인용을 구분 |
| `produced_at`, `registered_at`, `last_modified_at` | 생산·등록·최종변경 시각 | 원천의 어떤 날짜 필드인지 명시 |
| `canonical_url` | 공개 상세 화면 URL | 수집 시 HTTP 성공 확인 |
| `raw_payload_hash`, `normalized_content_hash` | 원천 변경·정제 변경 감지 | SHA-256 등 일관된 방식 |
| `retrieved_at`, `parser_version`, `robots_checked_at` | 재현성·감사 | 수집 실행마다 기록 |

`conclusion_text`는 LLM이 만든 요약이 아니라, 공식 요지 또는 회신 원문에서 규칙으로 찾아낸 문장만 저장한다. 추출이 불명확하면 빈 값과 `conclusion_extraction_status=unresolved`를 저장하고, 답변에서 결론처럼 단정하지 않는다.

### 4.2 검색 청크

청크는 고정 글자 수가 아니라 의미 단위로 만든다.

1. `METADATA`: 문서유형·세목·문서번호·생산일자·등록일자·원문 링크
2. `ISSUE`: 제목·공식 요지·질의의 쟁점
3. `FACTS`: 질의 사실관계
4. `REPLY`: 회신 전문을 문단 단위로 분리
5. `CONCLUSION`: 결론으로 확인된 회신 문장
6. `LEGAL_GROUNDS`: 상세 화면의 관련 법령 목록 및 원문에서 추출한 조문 인용

`REPLY`가 길면 문단 경계를 우선하고, 각 청크에는 앞뒤 문단 ID만 연결한다. 모든 청크에 `source_document_id`, `document_number`, `document_type`, `tax_name`, `produced_at`, `article_refs`, `section_type`, `content_hash`를 붙인다. 이 방식은 앞 600자 같은 일괄 절단을 제거하면서도, 답변에 필요한 결론·근거 조문만 작은 Evidence Pack으로 전달할 수 있다.

### 4.3 조문·그래프 관계

관계는 원문에서 검증 가능한 것만 만든다.

```text
(TaxInterpretation)-[:HAS_SECTION]->(InterpretationSection)
(TaxInterpretation)-[:INTERPRETS {source:"official_related_law"}]->(LawArticle)
(TaxInterpretation)-[:CITES {source_text:"…"}]->(LawArticle)
(LawArticle)-[:IMPLEMENTED_BY]->(EnforcementDecreeArticle)
(LawArticle)-[:IMPLEMENTED_BY]->(EnforcementRuleArticle)
```

`INTERPRETS`는 상세 화면이 명시한 관련 법령/조문일 때만 생성한다. 회신 본문에서 인용한 조문은 `CITES`로 별도 저장해 과도한 의미 해석을 막는다. 답변은 법령 조문을 1순위, 직접 관련된 세법해석례의 `CONCLUSION`/`FACTS`를 2순위로 재정렬한다.

## 5. 증분 갱신 설계

### 5.1 복합 워터마크

최종변경일 하나만으로는 늦게 등록된 과거 생산 문서와 화면 수정 문서를 놓칠 수 있다. 세목·문서유형별 커서에 아래 값을 함께 보관한다.

```json
{
  "tax_code": "303",
  "document_type_code": "02",
  "last_registered_at": "…",
  "last_produced_at": "…",
  "last_modified_at": "…",
  "last_source_document_id": "…",
  "last_successful_run_at": "…",
  "overlap_days": 14
}
```

갱신 순서는 다음과 같다.

1. 실행 시작 시 robots 정책과 파서 호환성 검사를 한다.
2. 세목·문서유형별로 `등록일자` 기준 워터마크보다 14일 앞선 구간부터 목록을 다시 읽는다.
3. `source_document_id`가 신규이거나 `last_modified_at`/원시 페이로드 해시가 달라진 문서만 상세 조회한다.
4. 상세 원문은 원시 응답과 정제본 해시를 모두 비교한다. 정제 규칙만 바뀐 경우 임베딩·청크·관계만 재생성한다.
5. 문서가 목록에서 사라졌다고 즉시 삭제하지 않는다. `source_status=not_seen`으로 표시한 뒤 다음 성공 실행에서 재확인한다.
6. 모든 큐가 성공한 경우에만 해당 커서를 전진시킨다. 실패한 큐의 커서는 유지한다.

### 5.2 중복·버전 키

정규 문서 키는 `NTS:{source_document_id}`다. 문서번호는 업무상 식별자이지만 정정·재등록 가능성이 있으므로 단독 고유키로 사용하지 않는다. 문서의 변경 키는 아래를 권장한다.

```text
source_document_id + last_modified_at + raw_payload_hash
```

관련 법령 목록·질의·회신 중 하나라도 바뀌면 `normalized_content_hash`가 달라져 관계·청크·임베딩을 다시 만든다. 폐지 법령과 달리 해석례는 삭제하지 않으며, 답변 시 생산일·등록일과 현재 법령의 시행일 차이를 보여준다.

## 6. 검색 및 답변 고도화

### 6.1 검색 파이프라인

1. 질문에서 세목, 조문, 법인 유형, 기간, 거래·사실관계, 계산 의도를 추출한다.
2. 법령 조문을 정확·전문·벡터 검색하고, 해당 조문에서 시행령·시행규칙과 명시 관계를 1-hop 확장한다.
3. 동일 조문/세목/핵심 쟁점으로 세법해석례의 `ISSUE`, `CONCLUSION`, `REPLY`를 검색한다. 단순 제목 일치보다 질의 사실관계와 회신 결론의 결합 점수를 높게 준다.
4. 문서유형 다양성 제약을 적용한다. 법령 1건 이상을 확보한 뒤 세법해석례는 최대 2건, 판례·결정례는 최대 1건을 보강한다.
5. 같은 결론을 반복하는 청크는 문서번호 단위로 군집화하고 최고 점수 하나만 Evidence Pack에 넣는다.
6. LLM에는 핵심 결론·적용 요건·근거 조문·유사 해석례의 사실관계 차이만 전달한다. 전체 원문은 사용자가 "근거 원문"을 열었을 때만 표시한다.

### 6.2 답변 품질 계약

세법해석례를 사용할 때 모델 출력은 다음을 모두 충족해야 한다.

- 법령명·조문을 먼저 제시한다.
- 해석례는 `문서유형 · 문서번호 · 생산일자 · 원문 링크`로 표시한다.
- 해석례의 질의 사실이 현재 질문과 같은지, 다른지, 제공되지 않아 비교할 수 없는지를 구분한다.
- 관련 조문과 해석례가 없으면 "없다"고만 끝내지 않고, 어떤 세목/유형/기간까지 검색했는지와 필요한 사실을 짧게 밝힌다.
- Evidence Pack 밖의 문서번호·공제율·판례 결론을 인용하지 않는다.

## 7. 품질 평가와 운영 지표

### 7.1 수집 품질 게이트

| 항목 | 통과 기준 | 실패 시 처리 |
| --- | --- | --- |
| 원천 식별 | 공개 문서 ID·정규 URL 존재 | 저장 보류 |
| 필수 본문 | 제목·문서번호·요지 또는 질의/회신 중 하나 존재 | `incomplete` 격리 |
| 날짜 정합성 | 생산일 ≤ 등록일(둘 다 있는 경우) | 경고 및 원시값 보존 |
| 법령 관계 | `INTERPRETS`는 공식 관련 법령 목록에서만 생성 | 관계 생성 제외 |
| 버전성 | 원시·정제 해시 및 파서 버전 존재 | 다음 단계 진행 금지 |
| 중복 | 동일 원천 ID는 하나의 활성 버전 | 버전 이력으로 병합 |

### 7.2 검색 평가 세트

실제 업무 질의에서 법인세·부가가치세·조세특례 각각 최소 30개를 익명화해 만든다. 질의마다 정답 법령 조문, 있으면 해석례 문서번호, 허용되는 보강 근거, 절대 인용하면 안 되는 문서를 전문가가 표시한다.

- `law_article_recall@5`: 정답 조문이 상위 5건에 있는 비율
- `interpretation_recall@10`: 필요한 해석례가 상위 10건에 있는 비율
- `citation_precision`: 답변에 표시한 근거 중 실제 Evidence Pack에 존재하는 비율
- `duplication_rate`: 같은 결론을 반복한 근거/문장 비율
- `unsupported_claim_rate`: Pack 밖의 수치·문서번호·결론을 단정한 비율
- `freshness_lag`: 국세청 등록/변경 시점부터 로컬 반영 시점까지의 시간

점수는 수집 건수보다 우선한다. 특히 법령 조문 누락, 잘못된 조문 연결, 출처 없는 공제율·가산세율 단정은 차단 규칙으로 처리한다.

## 8. 현재 구현과의 차이 및 우선 실행 순서

현재 구현은 공식 공개 화면의 목록·상세 요청을 사용하고 robots 확인, 문서 ID·최종변경일 비교, 세목/유형별 제한 수집을 이미 갖췄다. 구체적으로 사전답변·질의회신·과세기준자문·고시서면질의와 법인세·부가가치세·조세특례 조합별 최신 20건을 기본값으로 조회한다. 상세의 제목·요지·본문·관련 법령을 하나의 `content` 문자열로 저장하고, 변경 확인도 목록의 최종변경일(`version`) 하나에 주로 의존한다.

이 방식은 빠른 PoC에는 적합하지만 다음 문제가 있다. (1) 생산일자·등록일자·사실관계·질의·회신·주제어·원시 응답이 분리 보존되지 않아 같은 문서에서 "질문"과 "결론"을 구별하기 어렵고, (2) 최신 표본 밖의 유사 사례를 찾지 못하며, (3) 목록의 날짜가 그대로여도 상세의 관련 법령 또는 본문이 바뀌는 경우를 독립적으로 감지하지 못하고, (4) 관련 법령이 문자열이므로 법령 조문 그래프와 결정적으로 연결되지 않는다. 따라서 아래 순서를 권장한다.

1. **수집 메타데이터 보존**: 목록/상세의 생산·등록·수정 일자, 문서번호, 세목, 유형, 원시 해시, 파서 버전을 별도 컬럼/JSON으로 보강한다.
2. **구조 청킹**: 질의·회신·결론·관련 법령을 구분해 청킹하고 기존 앞부분 절단을 제거한다.
3. **결정적 조문 연결**: 공식 관련 법령 목록과 원문 조문 표기를 정규화해 `INTERPRETS`/`CITES` 관계를 만든다.
4. **연도별 백필 큐**: 최신 N건 방식을 유지하되 워터마크·중복 기간·재개 커서를 추가해 단계적으로 범위를 넓힌다.
5. **평가 게이트**: 위 평가 세트에서 법령 조문 검색과 근거 인용 정확도가 통과한 세목부터 챗봇 기본 근거로 활성화한다.

## 9. 공식 근거 링크

- [국세법령정보시스템 메인](https://taxlaw.nts.go.kr/): 세법해석례와 판례·결정례를 별도 메뉴·자료군으로 제공함을 확인.
- [세법해석례 전체 해석례](https://taxlaw.nts.go.kr/qt/USEQTJ001M.do): 사전답변·질의회신·과세기준자문·고시서면질의, 세목·검색어·등록일자·생산일자 조회를 확인.
- [주요 해석사례](https://taxlaw.nts.go.kr/qt/USEQTI001M.do): 문서번호와 등록일자를 포함한 공개 해석사례 표시를 확인.
- [국세법령정보시스템 robots.txt](https://taxlaw.nts.go.kr/robots.txt): 금지 경로를 실행 시점에 확인해야 하는 근거.
- [빠른 키워드 검색](https://taxlaw.nts.go.kr/is/USEISA001M.do): 시스템이 제공하는 자료군의 검색 화면이나, 위 robots 정책에 따라 자동 수집 경로로 사용하지 않음.
